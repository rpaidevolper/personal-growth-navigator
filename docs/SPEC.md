## 1. 願景與原則

**一句話**：讓任何工作者在 30 分鐘內知道「我現在在哪、我想去哪、差多少、這週該做什麼、不同走法 5 年後會變成誰」。

**使用對象**：先是擁有者本人，再擴展到任何職類、任何階段的工作者（技術與非技術皆可）。

**設計原則**
1. 單一 HTML、離線可用、資料只存在使用者瀏覽器；AI 永遠是加分選配，不是前提。
2. 一步一步帶：新用戶永遠知道自己在第幾步、下一步是什麼；每頁一個主要行動。
3. 資訊不過載：預設只給前 N 個、可展開；狀態值不超過 4 個；能力不超過 10 項（可自行加）。
4. 每個推薦都說得出理由（為什麼推薦我這個？依據是什麼？）。
5. 可重現、可比較：模擬固定 seed；多局並排。
6. 框架資料可被社群修正（Phase 2 外部化、Phase 3 共編）。

## 4. Persona 與能力框架（Phase 2 核心）

### 4.1 Persona
- **工作類型 track**：`tech` 技術 / `biz` 業務與行銷 / `ops` 營運與管理 / `pro` 專業服務（顧問、法務、財務、HR…）/ `creative` 創意與設計
- **職涯階段 stage**：`junior` 新鮮人（<3 年）/ `senior` 資深個人貢獻者 / `lead` 小主管 / `exec` 高階主管 / `expert` 獨立專家與自由工作者

### 4.2 框架結構
每套框架 = **4 項共通核心 + 6 項職類專屬 = 10 項**，每項 5 級描述（1 入門 / 2 基礎 / 3 熟練 / 4 進階 / 5 專家）。
```json
{ "id":"tech-senior", "track":"tech", "stage":"senior", "name":"技術 × 資深個人貢獻者",
  "source":"自訂；參考 SFIA 8 / O*NET", "contributor":"Eddy", "updated":"2026-11-xx",
  "comps":[ {"id":"comm","n":"溝通與說服","cat":"核心","lvd":["…","…","…","…","…"]}, … ],
  "roles":{ "角色名":{"d":"一句定位","tgt":{"comm":4,…}} },
  "certs":["常見證照…"] }
```
**共通核心 4 項（所有框架相同 id）**：`comm` 溝通與說服、`solve` 問題解決與決策、`exec` 專案執行與交付、`learn` 學習與適應。
**職類專屬 6 項**：由各框架定義（例：tech → 系統設計、程式與工具、資料、自動化與 AI 應用、品質與維運、架構思維；biz → 市場洞察、客戶關係、提案與談判、數據驅動行銷、通路與夥伴、產品知識…）。
- 使用者可**新增自訂能力**（第 11、12 項），來源可為 AI 追問發現。
- 現有 14 項自動化框架保留為 `tech-expert-automation`（擁有者專用，Phase 2 搬進 JSON）。
- 階段影響：同一 track 不同 stage 的差別主要在**目標等級**與角色卡，能力清單可共用；初版先做 5 track × 1 套，stage 只調目標等級的偏移（junior −1、exec 核心 +1）。

### 4.3 AI 客製（有 key 時）
輸入：職務、自介、persona。輸出（JSON schema）：對 10 項能力的名稱微調、每級描述改寫成該職類用語、建議 2 項額外能力。使用者可接受 / 退回預建。

## 5. AI 追問（grill 模式）

目的：用對話取代制式題目，找出使用者說不出來的能力與證據，並校正自評。
**邏輯（取自 grill-me）**：
1. 只問「前提已確定」的問題；每輪 1 題；上一題的答案決定下一題。
2. 從經歷切入，不問「你幾級」：「最近 6 個月最有成就感的一件事？」→「你負責哪部分？」→「結果怎麼量化？」→「卡在哪裡、怎麼解？」→「誰依賴你的產出？」
3. 答案模糊時追問具體例子；「不知道 / 沒做過」是合法答案，直接跳下一分支。
4. 停止條件：10 項能力各至少有一個證據或明確的「無」；或達 12 題上限；使用者可隨時結束。
5. 產出：每項能力 `{建議等級, 理由, 證據摘錄}` + 新發現能力清單 + 可直接存成經歷的項目。使用者逐項「接受 / 維持自評」。
實作：Claude，`output_config` JSON schema；對話歷史存在記憶體，不落地；無 key 時此步驟隱藏。

## 6. Role model 原型庫（Phase 2）

- 精選 15–20 位知名經理人 / 創業者，每位：姓名、一句公開形象、3–4 個核心特質、特質 → 能力權重（+1 / +2）、適合的 track、**免責**「依公開報導整理，非本人背書，不代表其真實能力」。
- 選擇後：目標等級 = 所選角色目標 + 特質加權（上限 5）；畫面顯示「他的特質 → 你要補的能力」對照。
- 有 key：可輸入任何人物，AI 依公開資訊產生同格式條目（標示 AI 生成）。
- 資料放 `data/rolemodels.json`，接受 PR。

## 8. 機會生成規則（Phase 2，取代手寫清單）

機會 = 能練到差距能力的實戰場域。五種通用型態：
| 型態 | 練到的核心 | 門檻 |
|---|---|---|
| 主導一個內部改善專案 | exec、solve、職類專屬 | exec ≥ 2 |
| 對外分享（社群、演講、文章） | comm | comm ≥ 3 |
| 帶人 / 內訓 / Mentor | comm、lead 類 | comm ≥ 3 |
| 跨部門提案 / 售前 | comm、solve、biz 類 | comm ≥ 3、solve ≥ 2 |
| 外部認證 / 競賽 / 作品集 | 職類專屬 | 該能力 ≥ 2 |
生成：對差距前 3 的能力，各產生 1–2 個機會，套入 persona 的職類語言；**卡片必附理由**：「因為你在『X』差 2 級，這個機會主要練 X；門檻『Y ≥ 2』你已達標（目前 3）」。有 key 時 AI 可把通用型態改寫成貼近使用者情境的具體題目。

## 9. 計畫的下一步（Phase 2）

- 每個計畫項目帶**起步清單** `steps[]`（可勾選）：
  - 證照：報名 → 取得教材 → 讀完大綱 → 模擬考 ≥ 80% → 正式考
  - 技能：找 1 個學習資源 → 做一個小專案 → 產出可展示的作品 → 用在工作上一次
  - 能力：挑一個實戰情境 → 執行 → 向一位同事 / 主管要回饋 → 記錄到成長紀錄
  - 機會：寫說帖 → 找 Champion → 提案 → 啟動
- **本週視圖**：依每週時數與項目優先序，列出「這週做這 2–3 件事」，可勾完成。
- 季度回顧：距上次回顧 > 90 天時總覽出現提醒卡，引導更新等級、整理紀錄、再跑一局模擬。
- 有 key：AI 依項目與使用者背景產生更細的學習路徑（資源、週次）。

## 10. 職涯模擬（已完成，規格凍結）

- 一步 = 一季；一局 20 季；結束結算對所有角色的達成度，取最高為「最接近的角色」。
- 狀態值（0–100）：專業深度 depth、商業影響力 impact、能見度 vis、精力餘裕 energy。初值由能力推導；energy 70。
- 每季 4 張行動卡 + 休養；可選 1–2；精力不足變灰。成功率：規則引擎 `0.4 + 0.12×(平均等級 − 難度) + 0.001×depth (+影響力/能見度項) − 精力<30 罰 0.2 + 進行中加 0.25`，夾在 0.1–0.9。AI（Claude 或 Jev）判斷時與規則各半混合。
- 成功：主要能力 +0.4、次要 +0.2，4 級以上減半；失敗：進度 +0.5 下季更易成功。精力：行動消耗 `h/(每週時數×13)×50`（上限 60），每季回復 15，休養 +30。
- 隨機事件 10 條，每季擲一次，總機率約 35%，權重受狀態值影響；精力 < 15 必觸發倦怠。
- 可重現：LCG 隨機數狀態存在 run 內。
- 結算卡：角色與達成度、起點 vs 終點雷達、20 格路線圖、亮點、完整紀錄、匯出成行動計畫。多局並排比較。
- Phase 2 連動：行動卡來源改為使用者的框架（§4）與生成的機會（§8）。
